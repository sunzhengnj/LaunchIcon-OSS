# LaunchIcon 开发包

这是 LaunchIcon 1.0 的可交付启动包：包含产品/技术单一事实源、可交互的高保真浏览器原型、Codex 持续开发指令，以及一张原创视觉参考图。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `LaunchIcon_PRD.md` | 1.0 功能边界、页面和交互规格、架构、数据、权限、双渠道策略、测试和验收标准 |
| `LaunchIcon_Prototype.html` | 不依赖网络或构建工具，双击即可运行的交互原型 |
| `LaunchIcon_Visual_Reference.png` | 原创主界面视觉概念，仅作审美和布局参考；不是产品资产，也不含 Apple 私有资产 |
| `CODEX_GOAL.md` | 可直接交给 Codex 的强约束开发目标 |

## 打开原型

在 Finder 双击 `LaunchIcon_Prototype.html`，或将它拖进任一现代浏览器。无需安装 Node、npm、服务器或联网。

推荐在 1440 × 900 左右的窗口中查看；原型也支持较小窗口缩放。它是交互、信息架构和动效参考，不是 macOS 原生 App，也不会扫描或启动真实应用。

## 原型内可试操作

- 点击任一应用图标，查看轻量按压与“已请求启动”的非真实反馈。
- 在搜索框输入名称，或直接键入字符；用 `⌘F` 聚焦搜索。
- 点击左右两侧箭头、分页圆点，或按 `←` / `→` 切换页面。
- 拖动一个图标到另一个图标中央，创建文件夹；点击文件夹可展开，点击背景、关闭按钮或按 `Esc` 关闭。
- 拖到图标边缘区域，重新排序。搜索状态下为了避免歧义，整理操作被禁用。
- `Esc` 按“文件夹 → 搜索 → 收起界面”的顺序处理；点击“重新打开”可恢复示意界面。

所有原型状态仅存在当前浏览器内存中，刷新即恢复默认样例。

## 交给 Codex 的方式

1. 将整个 `LaunchIcon_Dev_Pack` 文件夹复制到准备开发的 macOS 项目根目录（或把其中三份 Markdown 文档纳入 `Docs/`）。
2. 先让 Codex 阅读 `LaunchIcon_PRD.md` 与 `CODEX_GOAL.md`，再让它检查现有仓库的 `AGENTS.md`、工作区状态和可用 Xcode/SDK。
3. 要求它先完成 PRD 第 15 节的 API / 沙箱 spike，再按 M0→M4 和 P0→P2 推进。不要跳过 Direct / App Store 能力差异验证。
4. 每一个里程碑要求：可运行构建、相关自动化测试、真机或真实 UI 证据、变更摘要、尚未验证的边界。仅“编译通过”不算完成。

可直接使用以下提示语：

```text
请阅读 LaunchIcon_Dev_Pack/CODEX_GOAL.md 和 LaunchIcon_Dev_Pack/LaunchIcon_PRD.md，按其中约束在当前仓库启动并持续完成 LaunchIcon 1.0。先完成 API/权限 spike 和 M0；在每个里程碑运行测试、自检、记录决定并提交。不要停止在计划或 mock，直到 1.0 验收标准有真实证据，或遇到需要我做产品/权限决策的明确阻塞。
```

## 原型与最终产品的边界

原型只使用原创 CSS 几何图标、虚构应用名称和抽象渐变，不含或暗示 Apple 私有图标、壁纸、系统数据库或 API。真实产品必须遵循 PRD 中的公开 API、隐私和渠道限制；尤其 Mac App Store 的扫描、全局快捷键与外部应用启动能力须先实测，不得假设 Direct 版能力可直接迁移。
